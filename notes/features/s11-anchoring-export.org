* Scope and Acceptance
- =SdrAgent.Audit.AnchorSink= behaviour plus deterministic =FileSink=.
- =GitSink= publishes canonical signed statements to the private protected
  =chops/sdr_agent-audit-anchors= repository and returns commit/blob evidence.
- =OpenTimestampsSink= submits only hashes, persists pending proofs and appends
  upgraded proof receipts. Network coverage is =:external=; default tests use
  a fake calendar.
- Ed25519 signing uses OTP =:crypto=. Runtime receives the private key only via
  =bin/with-secrets= environment mapping; errors and receipts never contain it.
- An Oban worker anchors after configurable event-count / 15-minute thresholds;
  every export requests an anchor regardless of cadence.
- =mix sdr.audit.export= exports lead, agent-run, draft or sequence-range data.
  The signed bundle includes events, authorized payloads, anchors, receipts and
  key provenance. A verifier checks chain, hashes, signatures and available Git
  and OTS evidence and reports the strongest honestly proven assurance level.
- Every verify/export/read path calls =SdrAgent.Audit.record_access/5= and fails
  closed if the access row/event cannot be committed.

* Risks and Decisions
- No new library: OTP =:crypto= provides Ed25519; HTTP uses existing Req.
- Git anchoring is owner-domain evidence, not independent timestamp proof.
- OTS confirmation is asynchronous; pending evidence must never be reported as
  OTS-anchored.
- Anchor publication can partially succeed. The append-only receipt stream
  preserves each result and supports safe retry without rewriting an anchor.
- Repository creation/protection is an authorized external side effect. It is
  performed only after local behavior and command construction are verified.
- ADR evaluation: amend ADR-0002/0005 only for clarified executable formats or
  constraints; do not create a competing ADR for their already accepted design.
