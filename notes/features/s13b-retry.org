#+TITLE: Feature: S13b — operator retry that actually re-runs work
#+DATE: 2026-10-07

* Summary
S10b and S13a left operator retry inert. =Operations.retry_operation/2=
only flips an Operation =failed → running=, and =Agents.retry_run/2= only
creates a queued AgentRun. Nothing re-enqueues the work. A failed
WebhookEvent can reach =processed= in the lifecycle, but no operator path
leads there.

S13b makes operator retry execute the work, idempotently, with bounded
attempts and audit:
- failed, budget-exhausted or cancelled *agent runs*, both assignment
  (research) and reply-classification runs;
- *failed webhook events*.

It also adds admin-only UI retry buttons, with deny tests.

* Entity Model
#+BEGIN_EXAMPLE
Entity Model trigger: yes
Reason: changes backend action contracts (AgentRun :retry accepts an Operation; a new
WebhookEvent :request_retry action; Operation :retry actor narrowing) and adds invariants
(one retry per run, bounded retry chains, bounded webhook retries). No new entity, attribute
or migration is proposed.
#+END_EXAMPLE

** Questions for the soft-stop
1. Row 1 or 4 policy: narrow =AgentRun :retry= to ADM in the resource too
   (one source of truth), or keep REV there and gate only the orchestration?
2. Row 1 bound: 3 retries per original run. Acceptable?
3. Row 5: is re-running the original Oban job (args hold the bytes) right,
   rather than reading Payload content for a fresh job?

* Soft-stop v2 (revision for Codex verdict on =2d5f948=: NEEDS-REVIEW)
The v1 table above is superseded by this one. Rulings adopted: Q1 active ADM
only, at the resource and at orchestration; Q2 at most 3 retries after the

** A. Agent-run retry

| A1 | =SDR.retry_run(run_id, actor:)= (new, agent plane; the *only* operator retry path) | =run_id :: uuid=. ** B. Webhook retry

| # | Entity / action | Contract (typed) | Invariants and where they are enforced | Actor / Audit |
|---+-----------------+------------------+----------------------------------------+---------------|
| B1 | =Outreach.retry_webhook(event_id, actor:)= (new) | =event_id :: uuid=. Returns ={:ok, %{event_id, ordinal}}= (metadata only; the job bytes never leave the server), or a typed error with nothing written. | Guard =guarded?: true= (active ADM of the tenant; others refused and audited once, before validation). One =Audit.transaction=. *Locks:* WebhookEvent =FOR UPDATE= → the exact original job (=SELECT … FROM oban_jobs WHERE worker = 'SdrAgent.Outreach.WebhookWorker' AND args->>'webhook_event_id' = $1 FOR UPDATE=) → chain head. Checks: verdict =valid=; status =failed= (=received=, =processed= and =rejected= never rerun: =:not_failed=). Exactly one original job: zero is =:retry_window_expired= (pruned), more than one is =:ambiguous_job=. Job args =tenant_id= and =webhook_event_id= match. The carried =raw_body= decodes and hashes to =raw_body_sha256=, else =:job_corrupt=. Job state ∉ {available, scheduled, executing, retryable} (=:retry_pending=). Ordinal = previous =webhook.retry_requested= events for the event + 1, and must be ≤ 3, else =:retry_limit_reached=. Then B2 (audit), then =Oban.retry_job/2= in the same transaction. *Postcondition under the lock:* the job is =available= with =max_attempts > attempt=, else roll back (=:retry_noop=). Oban 2.24 returns =:ok= for a no-op and raises =max_attempts= to =GREATEST(max, attempt + 1)= without resetting =attempt=: the operator ordinal (1..3) is distinct from Oban's attempt number. | ADM. |
| B2 | =WebhookEvent :request_retry= (new update action) | No arguments; computed =ordinal :: 1..3=, =oban_job_id :: integer=. | =failed → failed= (no column change; =Transition= guard =from: [:failed]=). Appends =webhook.retry_requested= (ordinal, job id). | *Policy split by action:* =:request_retry= active ADM only; =:receive=, =:reject=, =:mark_processed=, =:mark_failed= and =:record_retry_failed= WHK only. There is no broad ADM write. |
| B3 | Processor (=Webhooks.process/4=) | Unchanged signature. | A =failed= event is processed only when its latest ledger entry among {=webhook.retry_requested=, =webhook.retry_failed=} is an *unconsumed* =retry_requested=. This is checked under the event lock, so a resumed or duplicate job cannot exceed the operator's bounded requests (otherwise =:done=, no-op). The bytes are still hash-checked under the lock. *Success:* =:mark_processed= (=failed → processed=, existing) resolves the event's Failure atomically. *Failure again:* new action B4; the event stays =failed=; no new Failure. | WHK. |
| B4 | =WebhookEvent :record_retry_failed= (new update action) | =class :: :validation_error \| :crash=, =reason :: string= (redacted). | =failed → failed=; consumes the pending request; appends =webhook.retry_failed= (ordinal, class, redacted reason). The existing Failure stays the single attention entry (no duplicate condition; its message is not rewritten). | WHK only. |

** Concurrency cases (tests planned)
- Two ADM retries of the same run race: the prior-run lock serialises them.
  The second sees the child and returns =:already_retried=; the Operation
  identity is the backstop.
- A retry races a late, cancelled-but-in-flight worker: =:prior_work_live=
  while its job is live, and =:prior_model_call_unsettled= while a call is
  =sent=.
- A retry races an assignment or hand-off on the same lead: the Lead lock
  serialises them; then the active-run check applies.
- Two ADM webhook retries race: the event lock serialises them, and the
  second sees the job =available= and returns =:retry_pending=.
- The Oban pruner deletes the job before a request: zero rows, so
  =:retry_window_expired= with nothing written. A job locked by the
  request cannot be pruned until commit.
