- *Soft-stop verdict:* PASS (inherited from S2; this plan is not a delta).
- *Implementation choices within the S2 contract* (flagged for the PR
  reviewer; none weakens suppression, approval, idempotency or audit):
  1. *One draft row, one revision row, one event each.* The Draft's
     =current_revision_id= FK to =draft_revisions= is =DEFERRABLE INITIALLY
     DEFERRED= (the revision references the draft and vice versa); the draft
     create or edit picks the new revision's UUIDv7 in a =before_action=,
     writes it on the draft, and inserts the revision (+ citations) in an
     =after_action= of the same transaction. A draft without its current
     revision cannot commit.
  2. *Approval binds what the reviewer saw.* =approve/3= takes the
     =draft_revision_id= and its hex =content_sha256= the reviewer reviewed;
     anything but the draft's current revision with that exact hash is
     refused (stale). The recipient email is snapshotted from the *current*
     Contact row (locked), the contact must be active, the recipient must not
     be suppressed (email or domain), and the campaign must not be completed
     or archived (a paused campaign may be approved; the S8b send gate
     refuses to send while it is paused).
  3. *Edit-then-approve records.* The approval's audit payload carries
     =revision_author= (user id or agent run id), =approver_authored_revision=
     and =diff_hashes= (sha256 hex of =diff_from_ai_baseline= and
     =diff_from_parent=, or nil) — server-computed arguments, never input.
  4. *Rejection* is an Approval row with verdict/status =rejected= (reason
     required) bound to the current revision, written in the same transaction
     as Draft pending_review → rejected (T).
  5. *Suppression side effects, lock order.* Before the suppression row (and
     its event) is written, the matching open leads (email: contact email =
     value; domain: contact email domain = value), their enrollments, their
     drafts and granted approvals are locked =FOR UPDATE= (lead → enrollment
     → draft → approval → chain head, the order every other writer uses), so
     a concurrent hand-off or approval either commits first and is undone
     here, or waits and sees the stopped lead. Then, in the same transaction:
     leads → stopped (=status_reason= "suppressed: <reason>"), enrollments →
     stopped (=stop_reason= =unsubscribe= for unsubscribe reasons, =bounced=
     for hard_bounce, =suppressed= otherwise), granted approvals →
     invalidated (=suppressed=), drafts pending_review/queued → cancelled
     (S8b also cancels pending/failed_retryable deliveries). Re-creating an
     existing suppression returns it with no event and no side effects.
  6. *Policy extension (S5 obligation).* Lead =:stop= and Enrollment =:stop=
     additionally authorize AGT, DLV, WHK and SEED *only* inside the
     Suppression create (private marker
     =SdrAgent.Sales.Checks.SuppressionContext=, set by no public API);
     Outreach-internal writes (Draft queue/unqueue/reject/cancel, Approval
     invalidate, revision and citation inserts) carry a second private marker
     (=SdrAgent.Outreach.Checks.InternalWrite=).
  7. *Suppression sources in S8.* =:manual= (ADM; =created_by_user_id= =
     the actor), =:from_reply= (AGT; =unsubscribe_reply= with a
     =reply_classification= Decision of the agent), =:seed= (SEED, dev/test
     only; reason =manual=, the ledger records the seeder as source). S9 adds
     the WHK sources and the =reply_id=/=webhook_event_id= columns. The source
     rules are DB check constraints where the column exists in S8
     (=unsubscribe_reply= ⇒ =decision_id=, =hard_bounce= ⇒
     =delivery_operation_id=) and action rules otherwise.
  8. *Real SuppressionCheck.* =SdrAgent.SDR.SuppressionCheck.Store= (agent
     plane, so the behaviour's dependency points downward) asks
     =Outreach.matching_suppressions/2=; configured in =config.exs=. The S7
     test asserting "no store exists yet" changes by contract to the store's
     answer.
  9. *Draft from the hand-off.* =HandOffProposal= creates the Draft and its
     agent revision (citations from =output.claims= and
     =output.personalization=) *in the hand-off transaction*, from
     =SDR.proposal/2= read inside it, so a committed hand-off always has its
     draft. A citation must name an accepted EvidenceClaim of the draft's lead
     whose text is verbatim in the body (re-checked deterministically).
 10. *Deferred: redraft.* =request_redraft= and agent revisions of an
     existing draft need an agent route for =sdr.draft.requested=, which no
     slice has yet; reviewers edit or reject. Recorded for S9/S10.
 11. *Seeded suppression stops lead 04.* The seed writes one =email=
     Suppression per =Fixtures.suppressed_contact_emails/0=; by S2 its side
     effect stops Harborline's open lead. The S5 seed assertion "every lead is
     new" changes by contract to "every lead but the suppressed contact's".
 12. *Diffs.* Line diffs (=List.myers_difference/2=) over ="Subject: …\n\n"
     <> body=; carried-forward citations are the parent's whose text is still
     verbatim in the new body, dropped ones are listed at the end of
     =diff_from_parent=.
 (S8b choices are recorded in the S8b section below when it is planned.)

* Implementation Notes

** S8a findings and further choices (flagged for review)
 13. *Unreachable invalidation dropped.* S2 DraftRevision: "creating a
     revision … invalidates any granted Approval of an older revision". A
     granted approval holds its draft in =queued= and a revision can only be
     added in =pending_review= (revoke returns it), so no granted approval of
     an older revision can exist when a revision is created; the code path is
     not built (TDD: no untested scope). The =newer_revision= reason stays in
     the enum. S8b's send gate re-checks the hash regardless.
 14. *Rejected approvals bind too.* A rejection names the reviewed revision
     and hash like a grant (a stale rejection is refused), so the record says
     exactly which content was rejected.
 15. *Read-time checks are internal.* The changes that check invariants
     (=DraftConsistency=, =RevisionRules=, =CitationRules=, =BindApproval=,
     =ApplySuppression=) read with =authorize?: false= inside the action's
     transaction, as =get_and_lock_for_update= and S5's =RelatedInState= do;
     nothing they read is returned.
 16. *Revision audit payload.* =outreach.revision.created= carries the
     citations (argument =citations=) so the join rows are covered by the
     parent's record hash and event (S2 "AE: in parent event");
     RevisionCitation has no event of its own and is not =__sdr_audited__=.
 17. *Terminal-immutable Draft and Approval.* Both reuse
     =SdrAgent.Audit.SQL.terminal_immutable/3=: terminal rows never change,
     non-terminal rows change only their lifecycle columns, and neither can be
     deleted. A test proves the Approval binding columns and a revoked row are
     frozen.
 18. *Domain suppression match* compares the contact email's domain exactly
     (no parent-domain matching).
