* Binding rules applied
- Web calls public domain APIs only (no Repo, no resource internals, no
  =Ash.load=); every call passes =actor: current_scope.user=.
- Data loads in =handle_params= and only on the connected render (the
  disconnected render is a skeleton), so an auditor's page load records
  exactly one AuditAccess and nothing is shown before it is recorded.
- Mutating events always call the domain, never a UI-side role check: an
  auditor's forged event is refused by =SdrAgent.Audit.Guard= (Forbidden +
  one =authz.denied=) and shown as an error. Controls are hidden for AUR.
- Approve/reject send the revision id and hex content hash rendered in the
  form (hidden inputs); a stale verdict is refused by =BindApproval= and the
  page shows the error with the now-current revision.
- Payload content (captured message, research source) only through
  =Audit.read_content/2= (=payload_view= AuditAccess for every role, fail
  closed). No secrets are displayed; no external fonts, CDNs or inline
  scripts were added.

* Implementation Notes (S10a)
1. *Stream empty states need ids.* LiveView 1.2 requires an id on every
   child of a =phx-update="stream"= container, including the
   =only:block= empty-state row (first GREEN run: 13 failures).
2. *Empty access target.* An auditor dashboard with no attention and no
   queue produced =target_ref ""=, which AuditAccess refuses (required) — the
   page was correctly withheld (fail closed). A list view with no records
   now records =target_ref "none"=.
3. *Formatter non-convergence.* =mix format= (Elixir 1.20.4) did not
   converge on a call whose last positional argument was a multi-line map
   followed by a keyword; the test binds the map to a variable instead.
5. *Recipient at confirmation (S8 review).* The grant binds the contact's
   current email under a lock, so the draft page shows the recipient in the
   binding box, posts the email it showed with the approve form, and re-reads
   the contact on submit: if the email changed, nothing is approved and the
   page shows the new recipient to confirm again (=#review-error=,
   =#binding-recipient=). Each approval lists the recipient it actually bound
   (=data-recipient=). RED 12/13 (no =#binding-recipient=), then GREEN. The
   auditor deny test now forges the full rendered form (recipient included),
   so its attempt still reaches the domain guard and is audited.
4. *Reviewer reads of users.* A reviewer may read only itself (S5), so
   approvals show "by you" / "by another operator" instead of names.
