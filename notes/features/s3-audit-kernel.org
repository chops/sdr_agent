* Canonical serialization (=sdr-canonical-json/1=)
Specified in =SdrAgent.Audit.Canonical=: UTF-8 JSON, object keys (atoms are
written as their names) sorted by byte order, no insignificant whitespace;
strings escape only =\"=, =\\= and bytes < 0x20 (as =\u00XX=, lowercase);
integers in decimal; floats in shortest round-trip form; =true=/=false=/=null=;
other atoms as strings; =DateTime= as UTC ISO-8601 with exactly six fraction
digits and =Z=; =Date= as ISO-8601; =Decimal= as a string; non-UTF-8 binaries
are rejected (callers hex-encode hashes). Event hash = sha256 over the
canonical bytes of every AuditEvent column except =event_hash= and
=canonical_bytes=.

* Required Tests
- [ ] Canonical encoding: key order, escaping, datetimes, floats; non-UTF-8 rejected; version constant.
- [ ] Bootstrap: singleton tenant, chain head, genesis =tenant.created= at sequence 1 with zero prev_hash, provenance event; idempotent.
- [ ] Append happy path: sequence, prev_hash chaining, sha256(canonical_bytes) = event_hash, trace/span ids non-zero hex from the current span, a span opened when none is active, actor/authorization/clock source/provenance/version refs recorded.
- [ ] Same transaction: a domain write that fails after its append leaves no event and the head unchanged.
- [ ] Tamper detection via raw SQL (triggers disabled in-test): column edit, deleted event (gap), re-hashed event (prev_hash break), chain head divergence, Payload content edit, audited domain row edit (record_sha256).
- [ ] Concurrency: N processes with real (non-sandbox) transactions append concurrently, some rolling back; sequence gap-free, chain verifies.
- [ ] Append-only triggers: UPDATE/DELETE/TRUNCATE rejected on every APPEND-ONLY S3 table; every listed table has its trigger; terminal-immutable tables reject terminal-row updates and immutable-column edits.
- [ ] Payload: dedupe by sha256 (insert-if-absent), content hidden on read, =read_content= returns content and writes one AuditAccess + event; denial for disallowed actors.
- [ ] verify_chain: ADM/AUR/AUD allowed and audited (AuditAccess chain_verify); REV denied with one committed =authz.denied=.
- [ ] Auditor guard: AUR denied on every S3 mutation path, each producing one =authz.denied=; ADM/REV/system allowed where S2 allows them.
- [ ] Agents: definition register idempotent / conflicting sha rejected / retire; AgentRun transition table equals declared transitions, forbidden transitions rejected, concurrent budget reservation never exceeds the max; ModelInvocation, ToolInvocation and Decision recorded with links, payloads, trace ids and events; Decision mode/kind validations and idempotency.
- [ ] RetentionMarker: supersedes lineage (one root, must supersede current); ADM only.

** Public audit API (for S5–S11)
- =SdrAgent.Audit.append/2= is the single append entry point; domain actions
  use the shared change =SdrAgent.Audit.Changes.AppendEvent= (after_action,
  same transaction; works with atomic updates). Options: =event_type=,
  =category=, =links= (event field ← record field), =tenant=, =arguments=,
  =version_refs: {mod, fun}=.
- Every new resource: =SetTenant= (tenant from actor), =TraceIds= (row
  trace/span ids), the auditor guard policy, a =trace_id= check constraint,
  =SdrAgent.Audit.SQL.append_only/1= or =terminal_immutable/3= triggers in
  =custom_statements=, and =def __sdr_audited__, do: true= when every write is
  audited (the verifier then checks =record_sha256= of the newest event
  against the live row).
- Lifecycles: =SdrAgent.Audit.Changes.Transition= (=from:=, =to:=) +
  =transitions/0= data + a table test (see =agents_test.exs=).
- Domain code interfaces wrap calls in =SdrAgent.Audit.Guard.run/3= with
  =%{resource:, action:, guarded?:, subject_id:}=; guarded calls inside a
  transaction must use =SdrAgent.Audit.transaction/1= (denials are appended
  after it ends), any other enclosing transaction raises.
- Payloads: =Audit.put_payload/3= (system actors), =Audit.read_content/2=
  (ADM/REV/AUR/AUD; AuditAccess first, fail closed); composite FKs via
  =SdrAgent.Audit.SQL.payload_fk/2=.
- =Audit.record_access/5= for S10 views and S11 exports;
  =Audit.verify_chain/1= returns =%{valid?, issues, last_sequence,
  events_checked}= (issue types in =SdrAgent.Audit.Verifier=).

** Deviations and findings during 4b (each with evidence)
1. *Budget counters use a row lock, not an atomic UPDATE.* Ash refuses
   expression updates of embedded attributes ("Embedded attributes do not
   support atomic updates with expressions"). The counter actions are
   =require_atomic? false= and re-read the run =FOR UPDATE= inside the action
   transaction (the alternative S2 "Risks" names). A real-concurrency test
   (12 processes, max 3) proves exactly 3 reservations succeed. Lifecycle
   transitions stay atomic (guard inside the SQL =UPDATE=).
2. *Unauthorized reads return an empty result, not Forbidden.* The project's
   Ash config filters statically forbidden reads. Test 6 of
   =policy_test.exs= was changed from =Forbidden= to ={:ok, []}= on that
   evidence (no data leaks either way).
3. *Direct-append test input.* The RED test passed an incomplete attribute
   set, so Ash reported =Invalid= before authorization; the test now forges a
   complete event (copied from genesis) and still expects =Forbidden= for an
   admin and for a kernel actor without kernel context.
4. *Auditor attempts are refused by the guard before the action runs*, so an
   invalid AUR attempt is also denied and audited (contract: every AUR
   mutation is denied and audited); resource policies remain as defence in
   depth.
5. *Guarded generic actions run with =transaction? false=.* Ash rolls back an
   enclosing transaction when an action that opened/joined it fails
   (=transaction_rollback_on_error?=); the kernel opens or joins the
   transaction itself instead, so a refused =verify_chain= inside
   =Audit.transaction/1= does not abort the caller (probe confirmed). S8: a
   refused *create/update* inside a caller's transaction did not abort it
   either in the probe, but guarded S8 actions should be re-probed.
6. *Append-only fixture.* The delete-rejection test hit an empty
   =tool_invocations= table (row triggers do not fire on zero rows); the
   setup now creates a tool invocation.
7. ModelInvocation also emits =model.invocation.sent= (plan choice 5) and
   AgentRun emits =agents.run.model_call_reserved|model_call_settled|
   tool_call_recorded= (S2 "AE: all writes").
8. Ledger-resource notifications are dropped (they have no notifiers);
   multi-step Agents writes send Ash notifications after commit.
