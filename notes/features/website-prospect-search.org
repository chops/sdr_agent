* Candidate decisions for bundled owner acceptance
- Exa only for v1, category company/people through /search. No Brave fallback,
  Exa Agent/Websets/enrichment, deep synthesis, direct LLM API, or Claude call.
- Server requests fixed api.exa.ai only. Never fetch result URLs directly.
  Optional explicit card open retrieves bounded source text via Exa /contents;
  it is a separate visible paid operation, not automatic per-result crawling.
- Results live in the owner's LiveView session, not new database tables/jobs.
  Disconnect/restart discards unsaved findings. This is interactive discovery,
  not scheduled/unattended discovery or a durable queued search.
- Plain-text query is disclosed as being sent to Exa. No CRM rows, campaign
  secrets, user email, model prompt or automatic whole-ICP upload.
- Search returns unverified company/person findings, not guaranteed work emails.
  Source text is provider-indexed content; unknown indexing/role dates stay
  unknown. Owner must complete unavailable required fields before saving.
- Company-first source path: select/confirm the company's official HTTPS URL
  and domain, then an explicit people search at that company; provider employment
  match is exact normalized company name and to=null, not proof of a current job.
  Explicit Get company page invokes /contents for exactly that confirmed URL,
  which must pass the existing public/company host rules. A directory/profile
  result never silently supplies the company domain. No global people mode in v1.
- Source map: confirmed website_url /contents text -> company_site; person
  profile text/highlights -> directory; company directory result -> directory.
  retrieved_on is provider-response receipt UTC date, not publishedDate.
  Excerpts are UTF-8-safe literal prefixes/slices <=2000 bytes for that source
  URL; no JSON-to-prose synthesis. Entity fields are separately labelled
  "Exa provider data, unverified"; excerpts never falsely substantiate all fields.
- Email is deliberately not extracted/prefilled in v1 (search person entities
  have no email field). Owner enters the required personal work address.
  This finds real companies/named people; it is not automatic email enrichment.
- Provision only EXA_API_KEY securely into the SDR service's root-only secret
  mechanism; no key in repository, browser, tool output, or process arguments.
  Do not modify research_harness or its running jobs.
- No automatic requests on page load/change, retries, fallback, paid enrichment,
  outreach or model spend. Owner clicks each paid operation. Provider dashboard
  spending limits remain authoritative; no new plan or account changes.
- No new durable app ledger for search disclosures/charges. Value-free counters
  aid diagnostics; Exa dashboard records billing. Sharing the existing key also
  shares quota/rotation with research_harness. Dedicated SDR key is optional.
- Account terms remain applicable; source excerpts are retained only when the
  owner submits the existing intake form, never bulk cached/resold. Exa terms
  sections1.1/4.1 tie API use to documentation, and4.2(a) restricts copying except
  as permitted. This is not a blanket third-party-content license or legal
  certification. Owner acceptance covers normal account use, not a waiver of
  Exa/source rights; any account-specific restriction must be honored.

* Required acceptance checks (before implementation)
1. Fixture company and person API responses become cited cards; missing fields
   remain blank, duplicate URLs collapse, source/profile host not misused as a
   company domain, old request results cannot overwrite a newer search.
   Nonmatched/ambiguous employer cannot prefill. Contents source URL equals the
   owner-confirmed website_url; directory/profile host never becomes domain.
   Entity facts and literal excerpts are visibly distinct; dates follow receipt.
   Provider /contents response host must match the confirmed website host;
   mismatch refuses with no excerpt/source URL substitution (review N1).
2. Unauthorized/auditor/ordinary/stale owner cannot trigger egress or see cards;
   owner revocation after request start withholds results. Selection ownership
   and request id enforced server-side; forged/stale card ids refused.
3. One in-flight paid operation per owner across tabs; explicit cancellation,
   disconnect and total deadline release it. Rate/timeout/auth/quota/oversize/
   malformed response errors produce closed UI outcomes; no automatic retries.
   Search subtree restart terminates all outstanding tasks, resets only ephemeral
   limiter state and never resends an uncertain request; charges may still occur.
   Late task messages are dropped by request id. Only a holder monitor releases
   the permit; a forged/stale result message cannot release another task (N2).
4. Fixed endpoint, TLS verification, no redirected credential forwarding, bounded
   request/response bytes and time. No caller-controlled headers/endpoints.
   Unsafe result URLs dropped; third-party images/favicon never auto-loaded.
5. Prefill changes clear old preview; existing OwnerIntake save success/deny/
   conflict/replay tests pass. Search/open/prefill alone leaves existing business,
   model, remote-call and operation counts unchanged.
6. Logs/telemetry/crash/error paths never expose API key/query/result/email/text;
   scoped sensitive metadata and closed errors, including provider HTTP bodies.
7. Browser rendering: loading/empty/error/cancelled/result states, escaped hostile
   source text, responsive cards; browser refresh loses unsaved findings honestly.
8. After activation approval, a small explicit live Exa smoke proves non-fixture
   company and person retrieval. Report actual results/charged requests, not
   guaranteed email or full ICP coverage. No real record save during smoke.
