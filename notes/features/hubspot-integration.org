#+TITLE: Feature: HubSpot CRM integration (design, entity delta, sliced plan)
#+DATE: 2026-10-07

* Summary
Design-only plan for a free HubSpot developer test account as the first real
CRM adapter (spec §17). The decision is recorded in
=docs/adr/0013-hubspot-crm-integration.md= (proposed, revision 2).

The plan covers:
- read-only import into Accounts, Contacts and Leads;
- HubSpot as an untrusted research source;
- outbox writeback with dry-run mode and a kill switch;
- polling sync.

This PR changes no code. Owner decision 2026-10-07: integrate with HubSpot,
test against a developer test account, and keep the app personal and local
(no hosting, no public webhook).

** Layering delta (ADR-0009 item 7 amendment, made when ADR-0013 is accepted)
#+BEGIN_EXAMPLE
Audit <- Accounts <- Operations <- Agents <- Sales <- Research <- Outreach <- CRM
#+END_EXAMPLE

- Lower domains keep only plain uuid refs to CRM rows.
- Binding checks inside lower-domain actions validate a lower-domain
  *Decision* (Agents), never a CRM row (ADR-0013 §3).
- Scoped content reads use an Audit-owned check module (=CrmContentScope=)
  whose private-context scope the CRM domain builds from authoritative rows.
  This follows the existing =ReconciliationScope= pattern.

** System actors (=SdrAgent.Actor= types; code)
- *CRS* =:crm_sync=: preflight, import, research-adjacent identity,
  planning.
- *CRW* =:crm_writer=: dispatch writes (Part B).
- *REC* (existing): API-call and write-operation sweeper, and
  reconciliation.

None of these may approve, assign, stop leads directly, edit drafts, manage
users, or lift suppressions.

** Not persisted (by design)
- *The service key* exists only in the gitignored sops file, then in the
  =CredentialHolder= process state (sensitive, redacted status). It is
  deleted from the OS environment at boot and scrubbed from every child
  launch.
- *Raw search pages and the properties of skipped (non-synthetic) records*
  are never persisted.

* Required Tests
Required per slice in ADR-0013 §§1–9. Part A:
- [ ] Gate serializes research, import and preflight concurrently: exactly
      one in flight, pacing respected.
- [ ] Gate: queue deadline returns before any reservation.
- [ ] Reservation: the cap is atomic under concurrency; a request is
      attributed to the reservation day across midnight; no refunds.
- [ ] Sweeper: reserved/sent rows go unknown.
- [ ] Child env: the canary is absent for ClaudeCLI, git and ots launches
      after boot. Holder state is redacted in crash reports.
- [ ] Echo: a response containing the canary key is withheld and a critical
      Failure opened.
- [ ] Spans hold no email, key or authorization data.
- [ ] Preflight: STANDARD, SANDBOX, APP_DEVELOPER and wrong-portal
      responses all refused; derived from the stored response only; epoch
      bump invalidates.
- [ ] Hermetic: no stub means refusal; foreign host, http and 3xx refused;
      the external hatch is unavailable without all four conditions; the CI
      guard holds.
- [ ] Import: skipped records persist no properties (dry run too); stale
      versions ignored; equal-timestamp tie; fingerprint unchanged;
      adoption and conflict; merge alias and conflict.
- [ ] Binding: direct-action binding denial for wrong tenant, portal,
      subject, kind, outcome or fingerprint (audited).
- [ ] Suppression: opt-out → Suppression; unknown opt-out blocks Lead;
      email change of a suppressed contact refused.
- [ ] Research: portal mismatch refused before I/O; watermark recorded;
      fenced prompt render; marker exclusion.
- [ ] Grants: allow and deny for CRS, CRW, REC, ADM and AUR on every grant
      in ADR-0013 §7; =:read_crm_content= outside scope denied and audited.

* Risks & Considerations
- Service-key beta status and every H0 unknown are blocking facts. H1a does
  not start until H0 records them.
- Without provider-unique =sdr_write_key=, an unknown create needs a human
  decision. That is accepted as the safe default.
- The gate is a single-node serialization point by design.
- STANDARD portals stay refused until the data-classification ADR.
