* B-1: Fake mode across the enqueue-to-perform interval
Reading =Runtime= as Fake when the command commits is insufficient:
current retry jobs normally resolve runtime configuration at perform.
An operator could switch to ClaudeCLI after enqueue. That must not make
this Fake-only slice a back door to a real retry, even though ordinary
reservation and grant checks would still apply later.

Revised resolution for review (accepts MF1):
- Require at least one source invocation, all provider =fake= and all
  known terminal (=completed= or =failed=), plus currently selected Fake
  runtime. Empty/unreadable/ambiguous history is conservatively blocked.
  Ledger generation is NOT the eligibility discriminator: current
  =ModelInvocation :reserve= unconditionally sets generation 2, including
  Fake, while =Agents= only admits real ClaudeCLI through the grant path.
  =InvocationProfile= records Fake profile =fake= and forbids grant and
  allocation on non-ClaudeCLI. Thus gen-2 Fake is a required positive;
  real gen-2 remains blocked. Historical gen-1 Fake is not excluded merely
  by its generation, but all other snapshot/source guards still apply.
- Source orchestration, never command args, stamps the retry job with
  =c1_retry_binding= containing exactly version =1=, expected_provider
  ="fake"=, new =run_id= and =retry_of_id=. This is a REFUSE-ONLY binding,
  not a provider override. No new column, responder/module or staging flag.
- At perform, recover the actual run from existing persisted job/Operation
  bindings first; never mutate a run selected by the stamp. Check the
  stamp against that run/parent/tenant/trigger and current known-Fake parent
  facts. The currently selected runtime AND normally resolved model must
  both be Fake. A stamped job cannot carry a separate =model= or responder
  override. If any predicate fails, refuse; never choose Fake, ClaudeCLI
  or another provider, and never repair the stamp.
- Existing unmarked jobs retain existing behavior, including the original
  AgentWorker's job-provider mechanism. This C1 change adds no override to
  ReplyWorker. Marker removal/forgery cannot be generated by the strict C1
  command/API; producer/worker tests pin both presence and exact bindings.

Retain blocked retry wherever this refuse-only source/job binding cannot
be supplied. This is the narrowed ADR-0015/ADR-0004 path Claude endorsed
in principle, not permission to implement before the revised entity PASS.
No positive real-provider path is proposed.

** Perform-time refusal lifecycle (MF2)
For an actual job-bound retry whose run is queued, the existing worker
actions may start it (=queued -> running=) and then fail it before Runner
or ModelProvider is called (=running -> failed=). Use existing
=status_reason: provider_error= with fixed content-free failure detail
=retry_binding_refused= (proposed identifier for reviewer ruling), never
the stamp, session, model options or raw exception. No model invocation,
reservation, grant charge or release is created. No automatic new run/job.

The run's existing =:fail= action opens its normal critical =run_stopped=
Failure for the NEW run and binds =attention_failure_id= to it. For an
assignment, fail the new Operation with that same live Failure (one
attention cause, not a second Operation Failure); a reply has no Operation.
The ordinary job returns only ={:error, :retry_binding_refused}=, so its
existing max_attempts=1 makes it discarded rather than retried by Oban.
The terminal transition/run lock and worker's terminal-state check make
repeat perform incapable of opening another Failure or reopening a
terminal run. This is not a new Failure upsert/dedupe record: new-run
identity plus the existing single terminal transition supplies dedupe.

The original Failure resolved by =AgentRun :retry=/=ResolveAttention= at
command commit stays resolved, with its original note and historic run
untouched. A later perform refusal does not undo that resolution or
resurrect the original cause; the new run owns its own new Failure. If the
job cannot be bound to an actual authorized run at all, discard/refuse the
job with the same fixed reason and mutate no guessed run or Operation.
If recording the terminal state itself fails, report a fixed worker error
and leave recovery to the existing stale-run path, not a claimed failed
run or a retry loop. No raw error can enter persisted job errors.

* B-2: bounded preview and authoritative execution
The preview considers only the final rendered page's Failure ids, not all
51-candidate producer rows or unrelated source history. It evaluates the
same relevant static source guards as execution: exact live Failure/run
pair, supported trigger/snapshot, known-Fake history, no child, bounded
retry depth, no active sibling, correct original job bindings/not-live,
lead/campaign and unassessed-reply state. It may refuse conservatively on
unavailable facts; source execution still repeats its full original
checks under lock, including the durable trigger and source policy.

Every id inside a batch receives its own tenant/actor authorization;
no first-row authorization stands for all ids. Whole-preview failure
blocks every requested retry, per-row failure blocks that row, and a
missing/unreadable source reference exposes no different hidden detail.
Session tokens never enter logs, spans, errors or returned guard facts.
No payload is loaded merely to decide a button. If some original source
guard cannot be evaluated from reviewed metadata, leave that case blocked
instead of adding raw audit-event/job content to the Home projection.
Only fixed safe block categories leave the source boundary. Per-source
failure cannot become an empty inbox or a change to scalar metrics.

The v1 item identity and Failure freshness encoding stay byte-compatible.
Volatile guard changes can disable/reject a previously displayed command
without changing its identity. After locks, changed Failure/token facts
give stale, source reserved/sent/unknown gives blocked/unknown_outcome,
and unsupported real/expected-provider facts give blocked/guard_not_available.
Already-retried or changed recovery context is stale/recovery_guard.
