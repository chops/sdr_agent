* B-1: Fake mode across the enqueue-to-perform interval
Reading =Runtime= as Fake when the command commits is insufficient:
current retry jobs normally resolve runtime configuration at perform.
An operator could switch to ClaudeCLI after enqueue. That must not make
this Fake-only slice a back door to a real retry, even though ordinary
reservation and grant checks would still apply later.

Proposed resolution for review:
- Require at least one source invocation, all generation-1 Fake and all
  known terminal (=completed= or =failed=), plus a currently selected Fake
  runtime. Empty/unreadable/ambiguous history is conservatively blocked.
- The source orchestration, never command args, stamps the newly created
  retry job with fixed Fake-only mode bound to that new run and its
  retry_of parent. No responder/module/provider from input is accepted.
- The worker honors that mode only for a correctly bound retry of the
  same known-Fake parent. It performs Fake or refuses; runtime changes
  after enqueue never convert it to ClaudeCLI or silently relabel a real
  parent's work as Fake. Existing jobs without the mode retain their
  existing behavior. No new run column or configurable staging bypass.
- Assignment's worker already has a closed job-provider mechanism;
  reply's worker currently has none. Supporting both is an existing-side
  backend job-contract delta, not something to slip in during GREEN.

Alternative: retain blocked retry wherever an equally strong reviewed
source/job binding cannot be supplied. Ask for this ruling before choosing
modules or adding RED tests. No positive real-provider path is proposed.

* B-2: bounded preview and authoritative execution
The preview considers only the final rendered page's Failure ids, not all
51-candidate producer rows or unrelated source history. It evaluates the
same relevant static source guards as execution: exact live Failure/run
pair, supported trigger/snapshot, known-Fake history, no child, bounded
retry depth, no active sibling, correct original job bindings/not-live,
lead/campaign and unassessed-reply state. It may refuse conservatively on
unavailable facts; source execution still repeats its full original
checks under lock, including the durable trigger and source policy.

No payload is loaded merely to decide a button. If some original source
guard cannot be evaluated from reviewed metadata, leave that case blocked
instead of adding raw audit-event/job content to the Home projection.
Only fixed safe block categories leave the source boundary. Per-source
failure cannot become an empty inbox or a change to scalar metrics.

The v1 item identity and Failure freshness encoding stay byte-compatible.
Volatile guard changes can disable/reject a previously displayed command
without changing its identity. After locks, changed Failure/token facts
give stale, source reserved/sent/unknown gives blocked/unknown_outcome,
and unsupported real/Fake-mode facts give blocked/guard_not_available.
Already-retried or changed recovery context is stale/recovery_guard.

* Review/test obligations to carry into the later plan
- Positive assignment AND reply retry through real domain APIs and exact
  Failure binding, with permanent assertions of one child/job and original
  source ResolveAttention behavior.
- reserved, sent, terminal-run sent, unknown/E1-normalized unknown, gen-2,
  non-Fake, empty and unreadable history all block with no source writes.
- Current-session revoke/demotion during independent lock waits; exact
  foreign/unreadable/nonexistent errors; resolved and mismatched Failure.
- Concurrent duplicate retry, changing child/live original job/source
  lifecycle; proper wait-chain barriers, bounded joined contenders.
- Runtime Fake -> ClaudeCLI change after enqueue cannot launch real work;
  both worker triggers, forged mode, wrong parent/run and pre-existing
  unmarked jobs covered without weakening their prior behavior.
- Preview query/row/deadline bounds for 1 and 50 rendered failures,
  no out-of-page reads, no per-row aggregates or domain/audit-head locks,
  occupied pool cancellation, whole/per-row failure safe blocking, and no
  preview work for non-admin roles.
- No content/session-token/raw-error canaries in outcomes, logs, spans or
  diagnostic audit. Invocation/grant/lease history unchanged on refusals.
