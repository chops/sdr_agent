- *Soft-stop verdict:* PASS (inherited from S2; this plan is not a delta).
- *Implementation choices within the S2 contract* (flagged for the PR
  reviewer; none weakens suppression, approval, idempotency or audit):
  1. *User trace ids.* The trace convention covers "every row of every new
     resource"; User is an existing resource and its S2 row lists no trace
     columns, so none are added. It gains =inserted_at=/=updated_at= (time
     convention for mutable resources).
  2. *No self-service flows.* Public registration, password reset,
     confirmation, magic link and remember-me are not configured (no email in
     the MVP; S2: "public registration disabled", AUR password only via ADM).
     The router drops the register/reset/confirm/magic-link routes that
     pointed at non-existent strategies. =sign_in_tokens_enabled? false=, so
     a browser sign-in runs the password read action exactly once (one audit
     event per attempt). The generator's unpinned =bcrypt_elixir= line is not
     added: bcrypt is already a locked, non-optional dependency of
     ash_authentication.
  3. *Disabled users.* "Disabled users cannot sign in": the sign-in and
     session-lookup (=get_by_subject=) reads only match =status = active=,
     and disabling a user revokes all of its tokens (existing
     log-out-everywhere add-on), so an open session ends too.
  4. *First admin.* Revised in review round 1 (Codex rejected seeder-only):
     a kernel-only =:bootstrap_admin= and =mix sdr.bootstrap_admin= create
     the first admin in any environment, only while the tenant has no users.
  5. *Seeder setup transitions.* S2 gives SEED "create" on Sales rows; a demo
     needs an active ICP, Sequence and Campaign, so SEED may also run their
     =activate= transitions — only in dev/test (=seeding_allowed?= config,
     checked by =SdrAgent.Audit.Checks.SeedingAllowed=), audited with actor
     =seeder=. Impersonating the admin in the ledger was rejected.
  6. *Sensitive attributes in events.* =AppendEvent= omits attributes marked
     =sensitive?= (=hashed_password=) from the payload's after-image and lists
     them under =redacted=; =record_sha256= still covers the full row.
  7. *From-state in events.* S2 Lead: "AE: every transition (from, to,
     reason, decision id)". Lead transitions run non-atomically with the row
     locked (=get_and_lock_for_update=) so the recorded =previous.status= is
     exact; =Transition= gains a =locked?: true= mode that checks the
     from-state on the locked row. Contact =change_email= records the old
     email the same way.
  8. *Lead → blocked* is authorized for AGT (the S2 policy cell omits it);
     the Failure side effect arrives with Failure in S7.
  9. *Lead → qualified/disqualified* runs only inside the Qualification
     create (a private context marker checked by policy), for agent
     qualifications of a lead in =qualifying=. Revised in review round 1:
     a human override that flips the outcome moves the lead qualified ↔
     disqualified in the same transaction, and is refused in any other lead
     state (operators then use =:stop=).
 10. *Human-override decision.* Qualification.decision_id is required, and
     humans never record Decisions; an override therefore carries the
     superseded row's =decision_id= (set server-side).
 11. *Agent qualification provenance.* =source: agent= requires
     =agent_run_id= equal to the decision's run, an =llm= decision of kind
     =qualification= whose invocation is =completed= and =valid=.
 12. *Grounding check input.* EvidenceClaim and ResearchArtifact creates take
     the artifact =content= as an argument; the server verifies
     sha256(content) = the artifact's =content_sha256= (content-addressed),
     so the check runs against the stored bytes without reading Payload
     content outside =read_content=. Offsets are Unicode code points,
     half-open =[char_start, char_end)=; the slice must equal =quote=
     byte-for-byte.
 13. *Artifact URLs.* =source_url= is =fixture://…= or http(s) on a reserved
     host (the synthetic-data guard). =freshness= is supplied by the
     retrieving action (S7), which computes it at retrieval.
 14. *Timezones (no new dependency).* Elixir ships a UTC-only timezone
     database, so S5 validates IANA zone names by shape only. CampaignEnrollment
     =advance_step= ("evaluated in campaign timezone") and its =→ completed=
     transition are deferred to S8, its only caller (DLV), which also needs a
     tz database for quiet hours and SendQuotaDay and must add it by ADR.
 15. *Hand-off queue.* =Sales.list_handoff_queue/1= returns replied leads
     (oldest hand-off first). Ordering by ReplyAssessment ("interested
     first") needs Outreach data, which Sales may not read (layering); S9/S10
     compose it above Outreach.
 16. *Campaign edits and archive.* =update= is allowed only in =draft= (the
     conservative reading: ICP/sequence/sender are fixed once active);
     =archive= is from draft, active or paused (completed is terminal).
 17. *Enrollment preconditions.* Besides the orchestrating action (S7), the
     create itself checks lead =qualified= and campaign =active= (both Sales).
 18. *Seed outcomes.* Leads are seeded =new=. S2 allows =qualified= /
     =disqualified= only with a Qualification (agent provenance) and
     suppression only with an Outreach Suppression row (S8), so the fixtures
     *designate* outcomes: accounts that fit / miss the ICP (≥ 1 each) and a
     contact whose Suppression S8 must seed (=SdrAgent.Demo.Fixtures=
     exposes them). Fabricating agent provenance in the seed was rejected.

** Deviations and findings during 4b (each with evidence)
1. *Password hash hiding.* AshAuthentication refuses a public
   =hashed_password= ("should have :public? set to false"), and field
   policies cover only public attributes, so a field policy cannot hide it.
   =SdrAgent.Accounts.Preparations.HidePasswordHash= deselects it on every
   read by a human operator (admin included); the kernel, internal re-reads
   and the AshAuthentication actions still load it. RED assertion changed
   from =%Ash.ForbiddenField{}= to =%Ash.NotLoaded{}= for operators.
2. *Wrong current password* is refused by AshAuthentication as
   =Forbidden= (=AuthenticationFailed=), not =Invalid=; RED expectation
   corrected (the refusal itself was already asserted).
3. *Sign-out route.* =GET /sign-out= renders AshAuthentication's
   confirmation LiveView; the sign-out itself is =DELETE /sign-out=
   (=mix phx.routes=). Controller test corrected.
4. *Session revocation on password change.* The log-out-everywhere add-on's
   global hook is conditioned on =changing(:hashed_password)=, evaluated
   before =HashPasswordChange= sets the hash, so it never fired (RED test
   kept the session valid). =change_password= and =set_password= now run
   =OnPasswordChange= explicitly; the =set_password= test also asserts
   revocation now.
5. *Anonymous denials (S3 change).* =SetTenant= added its "actor has no
   tenant" error while building the changeset, so a tenant-less caller of a
   guarded action got =Invalid= before authorization and no =authz.denied=
   was recorded. The error now comes from a =before_action= hook (after
   policies), so such calls are =Forbidden= and audited.
6. *S3 suites with real users.* Creating a real operator appends
   =user.created=. Three S3 assertions were re-baselined without weakening:
   the bootstrap test reads the head as the auditor CLI (no operator
   creation), the clean-chain test counts 8 events (genesis, provenance,
   the admin's =user.created=, five appends), and the forbidden-transition
   test creates the admin before counting. Concurrency readers use the
   auditor CLI; the cleanup list covers the new tables.
7. *Lock syntax.* AshPostgres takes =:for_update= or a string;
   =:for_share= crashed (=String.upcase/2=), so the string ="FOR SHARE"= is used.
8. *Domain function names.* =use Ash.Domain= injects deprecated =get/3=
   and =list/2,3=, so the generic reads are =fetch/3= and =list_records/2=
   (tests renamed).
9. *Fixture bug.* =claim_attrs/4= matched the quote against the default
   content even when the test supplied its own; fixed.
10. *Last active admin under concurrency.* Locking the target row first and
    then all admins could deadlock two crossing demotions.
    =KeepAnActiveAdmin= now locks all active admins (by id) and then the
    target, replacing the changeset data with the locked row. Added a
    real-concurrency test (two admins demote each other, three rounds):
    exactly one succeeds each round, one active admin remains, chain valid.
11. *Migrations.* Iteration used =mix ash.codegen --dev=; squashing dev
    migrations needs the shared dev database (Codex's), so the dev migration
    and dev snapshots (untracked, generated) were deleted and
    =mix ash.codegen s5_domain= generated the named migration fresh. The dev
    database was not touched. The users migration adds NOT NULL columns to
    the existing (empty, id-only) =users= table.
12. *Exact from-states.* Sales lifecycle actions run non-atomically on the
    row re-read =FOR UPDATE= (=get_and_lock_for_update= +
    =Transition locked?: true=), so events record the true previous status
    and a stale struct cannot move a row that has moved on (tested).
