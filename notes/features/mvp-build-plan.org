#+TITLE: Feature: SDR Agent MVP — build plan
#+DATE: 2026-10-06

* Summary
Build the audit-first SDR agent MVP (golden path demo, local only) as a
sequence of reviewed slices under ADR-0001's operating charter.

* Golden path (acceptance)
Executable test plus a short human demo script (=bin/demo run=):
1. Seed a fictional ICP, campaign, account and contacts (deterministic IDs/time).
2. Assign a lead (=sdr.lead.assigned=) → ResearchLeadFlow over fixture-backed
   search/CRM/web providers → ResearchArtifacts + EvidenceClaims.
3. Qualification (Zoi-validated) with evidence links.
4. PrepareOutreachFlow → OutreachProposal → Draft + immutable DraftRevision.
5. Reviewer approves in LiveView (approval bound to recipient + revision hash).
6. DeliveryOperation outbox → local capture adapter only; receipt recorded.
7. Signed, deduplicated simulated replies: one interested, one unsubscribe
   (deterministic suppression, follow-up cancellation).
8. Audit timeline reconstructs every step from Postgres alone; chain verifies;
   export bundle verifies; Tempo trace links resolve.

* Definition of done (every slice)
=bin/verify= green (format, compile --warnings-as-errors, tests), Ash codegen
=--check=, Credo, Reach advisory, secret scan, hermetic tests (no outbound
network), regression coverage, ADRs current, peer verdict recorded on the PR.

* Risks & Considerations
- Jido v3 beta / unpublished jido_ai: S1 decides; fallback per ADR-0003.
- Codex app-server is documented as experimental: acceptable for a local demo.
- Scope is large; slices stay small enough to review in one pass.
- Hooks fail open; permission prompts are bypassed (ADR-0001).
- Factory pins of ash 3.32.3, ash_authentication 4.14.2, ash_authentication_phoenix
  2.17.3, igniter 0.8.3 and usage_rules 1.2.7 have published advisories (several
  CRITICAL/HIGH in ash_authentication; found in S0 via =mix deps.get=). S0b bumps
  them to the minimal stable fixed releases and makes the CI audit blocking (ADR-0008);
  it must merge before S5 builds password auth on ash_authentication.
- =bin/verify= and =.workflow/project-facts.md= are hash-pinned by the factory receipt
  (=project-facts.md= despite its =seed_once= "project-owned" lifecycle), so S0 wires
  script tests through ExUnit (=test/scripts/=) and leaves both files unchanged.
